# Augmentation Lens

이 렌즈는 AI 제품이 사용자의 판단과 학습을 확장하는지, 사용자를 결과 승인자로
축소하는지 판정한다. 제품 정체성, 사용자-facing 행동, 권한, 관계를 다룬다.
아키텍처, 하네스, 저장 구조, 품질 게이트 같은 기술 구현 방식은 선택하지 않는다.

## 사용 조건

다음 제품 질문이 있을 때 사용한다.

- AI가 사용자의 결론을 대신하고 있는가.
- 자동 실행과 명시적 사용자 선택의 경계가 어디인가.
- AI 도입 뒤 사용자가 더 어려운 문제를 다룰 수 있는가.
- AI 출력이 원문과 근거로 들어가는 입구인가, 대체물인가.
- 반복 사용이 사용자의 판단과 질문 수준을 높이는가.

모델 성능, 비용, 속도, prompt, runtime, DB, CI 같은 기술 질문에는 이 렌즈를
사용하지 않는다. 그런 요소가 제품 행동을 제약하면 제약만 기록하고 owning
engineering workflow로 넘긴다.

## 1. 사람의 자리

가장 먼저 효율이 아니라 사람의 자리를 본다.

- replace: 사람이 하던 판단을 AI가 닫고, 사람은 결과를 승인한다.
- augment: AI를 쓴 뒤 사람이 더 복잡한 문제를 이해하고 자기 결론을 만든다.

AI가 일부 작업을 실행한다고 곧바로 replace가 되는 것은 아니다. 사용자가 결과의
근거를 이해하고, 교정하고, 다음 행동을 선택할 수 있는지가 경계를 가른다.

확인 질문은 다음과 같다.

- 이 제품을 쓴 뒤 사용자는 더 나은 판단자가 되는가.
- 사용자는 AI 결과를 거부하거나 다시 지시할 수 있는가.
- AI가 없어도 사용자가 배운 방법을 다시 사용할 수 있는가.
- 제품이 사용자의 결론을 먼저 닫지는 않는가.

## 2. 자율성과 권한

AI 행동은 `doing`, `suggesting`, `asking`의 연속선으로 본다.

- 되돌리기 쉽고 사용자별 결과 차이가 작으면 `doing`을 검토할 수 있다.
- 결과가 개인마다 달라지거나 되돌림 비용이 크면 `asking`을 앞에 둔다.
- 사용자가 판단할 근거는 있지만 직접 실행할 이유가 약하면 `suggesting`을 택한다.

각 행동에는 사용자가 계속 소유할 권한을 명시한다. 제품이 그 권한을 UI와 실제
행동에서 지키지 못하면 augment 판정을 내리지 않는다.

## 3. 원문과 근거

AI 출력은 원문과 근거로 들어가는 진입점이어야 한다. 요약이나 추천이 근거를
대체하면 사용자의 판단 자리가 줄어든다.

다음 행동을 관찰한다.

- AI 출력 뒤 원문이나 근거를 여는가.
- AI 제안을 반박하거나 수정하는가.
- 서로 다른 근거를 비교하는가.
- 결과를 자기 언어로 설명할 수 있는가.
- AI 출력만 기본 수락하는 비율이 높아지는가.

## 4. 행위 흐름

증강은 별도 교육 문구보다 반복되는 제품 흐름에서 만들어진다.

- 사용자가 먼저 문제를 제기하고 탐색을 시작하는가.
- AI는 다음 판단에 필요한 구조와 근거를 제공하는가.
- 사용자가 다음 행동을 선택할 수 있는가.
- 제품이 사용자의 선택 결과를 다시 학습 기회로 돌려주는가.

기능 수나 자동화 비율을 증강의 대리 지표로 사용하지 않는다.

## 5. 학습과 관계

관계는 친근한 말투가 아니라 반복해서 지키는 권한과 약속에서 생긴다. 기억은
사용자를 더 잘 예측하는 기능이 아니라 다음 판단을 자연스럽게 이어 주는 제품
정책이다.

- 사용자는 무엇이 기억되고 다음 행동에 어떻게 쓰이는지 이해하는가.
- 기억이 사용자의 선택지를 줄이지 않는가.
- 제품이 과거 선택을 근거 없이 현재 결론으로 고정하지 않는가.
- 반복 사용 뒤 사용자의 질문과 검토 능력이 높아지는가.

## 6. 행동 증거

설문만으로 augment를 판정하지 않는다. 가능한 범위에서 행동을 본다.

- AI 출력에 대한 명시적 반박과 재지시
- 요약이나 추천 뒤 원문 진입
- 근거 비교와 후속 탐색
- 자동 실행 취소와 대안 선택
- 사용자가 만든 질문의 구체성 변화
- 제품 없이도 다시 수행할 수 있는 방법의 습득

행동 증거가 없으면 `unknown`으로 둔다. 제품팀의 의도를 실제 사용자 변화로 바꾸어
말하지 않는다.

## 7. 판정

```yaml
augmentation_lens:
  subject: "{사용자가 계속 소유하는 판단}"
  product_behavior: "{AI가 doing|suggesting|asking 중 무엇을 하는가}"
  evidence: ["{관찰된 사용자 행동}"]
  replace_signals: ["{사용자 판단이 줄어든 행동 신호}"]
  human_authority: "{제품이 보존해야 할 권한}"
  verdict: "{augmentation|replace-risk|unknown}"
  validation: "{다음에 확인할 사용자 행동}"
```

판정은 제품 행동에만 적용한다. 기술적 원인이 의심되더라도 해결 구조를 제안하지
않는다. 사용자-facing 제약을 적고 owning engineering workflow로 handoff한다.

## 8. 미끄러짐 신호

- AI 요약이 원문 독해를 대체한다.
- AI 제안이 기본 수락되고 거부 사례가 사라진다.
- 사용자가 근거를 따라가지 않는다.
- 사용자가 결과를 자기 언어로 설명하지 못한다.
- AI 도입 뒤 질문 수준과 선택지가 줄어든다.
- 기억이 과거 선택을 현재의 자동 결정으로 바꾼다.

하나의 신호만으로 단정하지 않는다. 같은 행동도 제품 맥락에 따라 다르게 읽힐 수
있다. 확인할 행동과 재검토 조건을 함께 남긴다.
