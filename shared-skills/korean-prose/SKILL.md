# Korean Prose — 한국어답게 쓰고 다듬기

LLM이 뜻을 정확히 전하면서 한국어 어법에 맞고 자연스럽게 읽히는 글을 쓰도록
돕는다. 교정의 우선순위는 의미 보존, 문장 호응, 자연스러운 표현, 문체 정리다.
이미 뜻이 분명하고 자연스러운 문장은 그대로 둔다.

이오덕의 『우리 글 바로 쓰기』와 사용자가 제공한 12쪽 발췌·정리 PDF를
참고한다. PDF는 한국유방암학회 투고자를 위한 자료로, 원전 전권이 아니다.
생활에서 쓰는 말로
쉽게 표현하려는 방향을 참고하되, 저자의 문체론과 현행 어문 규범, 이 스킬의
실무 지침을 구분한다. 문헌의 확인 범위와 적용 근거를 점검하거나 확장할 때는
[문헌 참고 기록](references/uri-geul-baro-sseugi.md)을 읽는다. 아래 교정 예시는
이 스킬을 위해 만든 예시이며 책에서 가져온 문장이 아니다.

## 적용 범위와 경계

한국어 문서, 인수인계 기록, 설계 노트, 기술 가이드, README, 정책 문서,
PR 설명과 커밋 본문의 한국어 산문에 적용한다. 표 안의 설명도 대상이지만,
코드·명령·경로·식별자·스키마·기계가 읽는 값은 문체 교정을 이유로 바꾸지 않는다.
LLM judge의 영문 프롬프트는 이 스킬의 대상이 아니다.

Story Chain 본문은 `mission-control`의 절차와
`shared-skills/mission-control/references/human-authority-prose.md`의 전용 문체
기준을 함께 따른다. `/about` 문구의 의미와 검증은 `about-prose`가 소유한다.
해당 문서의 전용 문체는 그 범위에서 적용하며, 일반 한국어의 문법적 정오로
확대하지 않는다. 제품 의미·용어·개인정보 공개 정책의 결정은 각 소유 문서를
따른다. 한국어 교정만으로 그 결정을 바꾸지 않는다.

## 의미부터 보존한다

- 누가 무엇을 했는지, 대상과 수량, 시간과 순서, 조건과 예외, 부정의 범위를
  먼저 확인한다. 문장을 줄이거나 나눌 때도 이 관계를 유지한다.
- 사실, 추정, 가능성, 요청, 의무를 구별한다. “할 수 있다”를 “한다”로,
  “권한다”를 “해야 한다”로 바꾸어 확실성이나 의무를 높이지 않는다.
- 원문이 여러 뜻으로 읽히면 주변 근거에서 뜻을 확인한다. 확인할 수 없으면
  임의로 행위자나 인과관계를 채우지 말고 모호한 지점을 알린다.
- 인용은 원문과 출처를 보존한다. 풀어 쓴 문장은 직접 인용으로 표시하지
  않는다. 설명용 가상 사례는 사례임을 밝히고 실제 발언이나 관찰과 구별한다.
- 익명화가 필요한 글은 해당 공개 정책을 따르면서 인원수와 의견의 범위를
  보존한다. 한 사람의 의견을 “사용자들 의견”으로 바꾸지 않는다. 공개된
  문헌의 저자와 서지 출처를 개인정보 익명화와 혼동하지 않는다.

## 어법과 문장 구조를 점검한다

### 호응과 조사

주어가 서술어와 맞는지, 서술어에 필요한 대상이 있는지 확인한다. 조사는
문장 안에서 맡은 역할과 뜻에 맞게 쓴다. 문맥으로 분명한 주어는 생략할 수
있지만, 행위자가 바뀌는 곳에서는 다시 밝혀 준다.

| 초안                                                 | 수정                                             | 이유                                     |
| ---------------------------------------------------- | ------------------------------------------------ | ---------------------------------------- |
| 이 기능의 장점은 결과를 비교할 수 있다.              | 이 기능의 장점은 결과를 비교할 수 있다는 점이다. | 주어인 “장점”에 서술어를 맞춘다.         |
| 이 결과는 기존 연구와 다르지 않다라는 뜻이다.        | 이 결과는 기존 연구와 다르지 않다는 뜻이다.      | 간접 인용에 맞는 어미를 쓴다.            |
| 사용자는 결과를 검토하고, 필요한 논문의 저장을 한다. | 사용자는 결과를 검토하고 필요한 논문을 저장한다. | 나란히 놓인 행동을 같은 구조로 표현한다. |

“이 패턴의 특징은 단순한 구조이다”처럼 명사에 “이다”가 붙은 완결된 문장은
쓸 수 있다. 동사로 바꾸는 것 자체를 교정의 목표로 삼지 않는다.

### 수식 범위와 문장 연결

수식어는 꾸미는 말 가까이에 놓고, “이것”, “그”, “해당”이 무엇을 가리키는지
확인한다. 부정어와 “모두”, “일부”, “만”의 위치를 바꿀 때는 뜻이 달라지는지
살핀다. “모두 성공한 것은 아니다”를 “모두 실패했다”로 고치면 안 된다.

한 문장에서 관계를 따라가기 어려우면 나눈다. 조건·이유·대조가 한 문장에
있어야 더 잘 이해되면 복문을 유지한다. 문장을 나눈 뒤에도 접속 표현이나
대상을 밝혀 관계를 이어 준다. “그러나”, “따라서”는 실제 대조나 인과가 있을
때 쓴다. 시간과 조건을 나타내는 표현도 문맥을 보고 고른다.

### 시제·높임·맞춤법

완료한 일, 진행 중인 일, 예정된 일을 구별한다. 독자와 문서에 맞춰
“한다”체나 “합니다”체를 선택하고, 같은 서술 층위에서는 일관되게 쓴다.
요청과 명령, 의무는 종결 표현만 바꿔 서로 대신하지 않는다. 인용문은 원래
문체를 유지할 수 있다.

맞춤법·띄어쓰기·문장부호는 별도로 확인한다. 예를 들어 “할수 있다”는
“할 수 있다”로, “검토한지 사흘”은 “검토한 지 사흘”로 고친다. 판단이
불확실하면 국립국어원의 어문 규범이나 표준국어대사전에서 해당 항목을
확인하고, 찾지 못한 규칙을 만들어 단정하지 않는다.

## 한국어 표현을 자연스럽게 고른다

뜻이 같은 범위에서 독자가 익숙하게 쓰는 말을 고른다. 명사를 겹치거나
외국어 문장 구조를 그대로 옮겨 행위와 관계가 흐려졌다면 풀어 쓴다.
특정 단어나 문형이 보인다는 이유만으로 번역체라고 판정하지 않는다.

| 다듬을 표현                  | 수정 예                 | 적용 조건                                                   |
| ---------------------------- | ----------------------- | ----------------------------------------------------------- |
| 결과에 대한 확인을 수행한다. | 결과를 확인한다.        | 별도의 수행 절차를 뜻하지 않을 때 명사구를 동사로 푼다.     |
| 설정의 변경의 영향           | 설정 변경이 미치는 영향 | 관계가 같은지 확인하고 겹친 조사를 줄인다.                  |
| 검토가 진행되어지고 있다.    | 검토가 진행되고 있다.   | 불필요하게 겹친 표현을 줄이고 진행 의미는 남긴다.           |
| scope가 좁다.                | 범위가 좁다.            | 일반적인 범위를 뜻할 때 한국어로 쓴다. 식별자라면 보존한다. |

피동문은 행위자를 모르거나 대상의 상태를 중심으로 설명할 때 쓸 수 있다.
능동문으로 고치려고 행위자를 지어내지 않는다. “의”, “적”, “것”, “경우”나
한자어·외래어를 일괄 삭제하지 않는다. 쉬운 말로 바꾸어도 전문적인 구별과
뜻이 유지되는지 확인한다.

함수명, 타입명, 파일 경로, 제품명과 정의된 전문 용어는 정확히 쓴다.
일반 설명에 섞인 영어는 자연스러운 한국어로 풀고, 필요한 전문 용어는
독자가 이해할 만큼 설명한다. 기울임이나 굵은 글씨는 의미를 강조하는
편집 수단이며 영어 사용의 문법적 정오와 관계없다.

비유는 뜻이 분명하고 이해를 도울 때 쓴다. 서로 다른 비유를 겹치거나
비유만으로 작동 방식과 근거를 대신하지 않는다. “마지막 1cm를 잡는다”처럼
무엇을 확인하는지 알 수 없는 문장은 실제 확인 대상과 방법을 먼저 찾는다.
근거 없이 “빠짐없이 검증한다” 같은 보장을 덧붙이지 않는다.

### 문맥에 따라 풀어 쓸 표현

발췌 자료의 표현 유형은 고칠 곳을 찾는 단서다. 낱말을 발견하면 먼저 그 말이
문장에서 맡은 역할을 확인하고, 뜻이 같은 범위에서 다듬는다. 다음 예시는
자체 작성했다. 자료의 주장을 확인하거나 예외를 더할 때는
[항목별 근거와 적용 한계](references/uri-geul-baro-sseugi.md)를 읽는다.

| 점검할 표현                    | 자체 교정 예                                                                  | 판단 기준                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| ‘적·성·상·하’가 붙은 추상 표현 | 이 설정은 일시적으로 적용한다. → 이 설정은 잠시 적용한다.                     | 속성·시간·조건을 쉬운 말로 밝혀도 뜻이 같을 때 고친다. ‘일관성’처럼 필요한 개념은 남긴다.  |
| 겹친 조사와 명사구             | 이전 버전으로부터의 설정 복사 → 이전 버전에서 설정 복사                       | 출처·대상·방향을 유지한다. 관계가 불분명하면 서술어를 보충하되 추측하지 않는다.            |
| ‘에 있어서’                    | 결과를 비교함에 있어서 기준이 필요하다. → 결과를 비교하는 데 기준이 필요하다. | 장소·대상·조건에 맞게 푼다. ‘파일이 폴더에 있어서 찾기 쉽다’의 존재·이유 표현은 유지한다.  |
| ‘에 의하여’                    | 이 기록에 의하면 검사는 끝났다. → 이 기록에 따르면 검사는 끝났다.             | 출처·수단·원인·행위자를 구별한다. 근거를 나타내는 말을 지워 사실의 단정으로 바꾸지 않는다. |
| 열거의 ‘등’                    | 제목, 저자 등으로 검색한다. → 유지                                            | 다른 검색 항목도 포함한다는 뜻을 보존한다. 전부인지 모르면 임의로 삭제하지 않는다.         |
| ‘및’                           | 제목 및 요약을 확인한다. → 제목과 요약을 확인한다.                            | 나란한 대상과 항목의 묶음을 유지한다. 긴 목록은 문장이나 목록 구조를 조정한다.             |
| ‘내지’                         | 작업은 2초 내지 4초 걸린다. → 작업은 2초에서 4초 걸린다.                      | 수치 범위와 선택을 구별한다. 범위의 변화까지 나오면 이전 범위와 이후 범위를 각각 밝힌다.   |
| 강조하는 ‘보다’                | 보다 쉽게 찾는다. → 더 쉽게 찾는다.                                           | 문체를 다듬는 선택이다. ‘이전보다 쉽게 찾는다’의 비교 조사는 유지한다.                     |
| ‘았었다·었었다’                | 예전에는 이 옵션을 사용했었다. → 현재 사용 여부를 문맥에서 확인한 뒤 판단     | 단순 과거로 줄여도 과거와 현재의 차이, 경험과 순서가 유지되는지 확인한다.                  |
| 겹친 피동                      | 변경 사항이 반영되어졌다. → 변경 사항이 반영되었다.                           | 겹침을 줄이되 완료·진행·의무를 보존한다. 자연스러운 ‘이 함수는 두 번 호출된다’는 유지한다. |
| 어려운 한자어                  | 다음 수순을 안내한다. → 다음 절차를 안내한다.                                 | 분야와 독자에 맞춰 고른다. 정확한 전문 용어는 풀어 설명하거나 그대로 둔다.                 |

수정 뒤에는 문장 전체를 읽는다. ‘및’을 ‘과’로 바꾸어 항목의 묶음이 달라지거나,
‘등’을 ‘따위’로 바꾸어 평가하는 어감이 생겼다면 다시 고친다. ‘검토에 의한
변경’처럼 원인과 행위 주체를 구별하기 어려운 표현은 근거를 더 확인하고,
확인할 수 없으면 교정을 보류한다.

## 문단과 형식은 내용에 맞춘다

한 문단은 중심 생각 하나를 발전시킨다. 문장 수보다 설명의 연결과 읽는
부담을 보고 나눈다. 비교에는 표, 나란한 항목에는 목록, 절차에는 번호를
쓴다. 항목 수만으로 산문과 목록을 결정하지 않는다.

제목은 내용을 찾기 쉽게 붙인다. “사용법” 같은 명사형과 “왜 필요한가” 같은
의문형 모두 쓸 수 있다. 코드 앞에는 목적과 전제를, 뒤에는 필요한 결과
해석을 적는다. 코드만 반복하는 설명은 줄이되 이해에 필요한 설명은 남긴다.

## 작성과 교정 순서

1. 독자, 글의 목적, 사실 근거와 원하는 문체를 확인하고 초안을 쓴다.
2. 원문이나 근거와 대조해 행위자·수량·조건·부정·확실성이 유지됐는지 본다.
3. 호응, 조사, 수식 범위, 시제와 높임, 맞춤법과 띄어쓰기를 점검한다.
4. 읽어 내려가며 뜻을 다시 짚어야 하는 문장과 불필요한 반복을 다듬는다.
   위 표현 유형을 점검하되 일괄 치환하지 않고 각 표현의 역할을 확인한다.
   문체 선호만 다른 자연스러운 문장은 유지한다.
5. 바꾼 문장을 앞뒤 문맥에서 다시 읽는다. 교정 이유를 어법 오류,
   모호성 해소, 표현·문체 개선 중 무엇인지 설명할 수 있어야 한다.

## 스킬 변경 검증

예시마다 수정 전후의 의미와 설명이 맞는지 확인한다. 자연스러운 문장을
유지하는 사례, 조건과 부정을 보존하는 사례, 뜻이 모호해 교정을 보류하는
사례도 함께 검토한다. 형식 검사 통과를 실제 생성 품질의 증거로 삼지 않는다.

정본인 `shared-skills/korean-prose/`를 고친 뒤 사본을 동기화하고 검사한다.

```bash
python3 scripts/sync-agent-skills.py --prune
npm run format:check
npm run guard:skills
npm run pk:validate
```

호출 설명이나 라우팅을 바꾸면 `skill-governance-steward`의 라우팅 평가 절차도
따른다.
